# 车机单板与插件资源业务约定

确认日期：2026-09-19。
本文记录用户确认的真实业务场景，供插件开发和 GUI 实现使用。它不是新的 Framework 或 DSL 合约，也不表示下面所有功能已经实现。

## 修改边界

- 插件功能在 plugins 目录内开发，不修改 Framework 核心、公共合约或 DSL。
- 允许调整总体 GUI 入口及展示，但不得改变核心架构、执行规则或资源所有权边界。
- 若现有架构确实不能满足需求，先说明具体缺口并与用户确认，不自行突破边界。
- 按简单约束实现；不为假设中的复杂场景扩展机制。
- 开发环境没有待测硬件，不扫描、探测或打开实际 COM 口；COM3 与本任务无关。
- 唯一环境文件由宿主管理，插件通过既有 WorkspaceContext 保存自己的配置，不私自读写其他插件的切片。

## 单板身份：已明确确认

1. 单板唯一编码就是 adb devices 第一列序列号。
2. 进入 fastboot 后仍使用同一编码。
3. 编码本身是单板的主键和逻辑名称。ADB 是发现、访问单板的接口；端口、连接状态、工作模式不是主键。
4. recovery、sideload、fastboot 分别显示，不合并为一个“升级模式”。
5. 离线、未授权、连接丢失和模式切换不删除单板登记或资源归属；工具查询失败不能伪装成单板离线。
6. 单板通过现有 devices 登记，插件资源通过已有顶层 device 字段关联这个编码。不在继电器等插件中另设一套单板身份。
7. 现有合约规定 ADB 类型的所有者维护 devices；这是登记入口的权限边界，不表示单板只有 ADB 在线时才存在。

## 物理资源与归属

| 资源 | 物理定位 | 单板内用途与约束 |
| --- | --- | --- |
| ADB / fastboot | 已确认 USB 的设备序列号 | 每块单板至多一个接口，模式变化仍属同一单板；执行命令、取得输出、拉取日志 |
| CH340 串口 | 环境配置指定的 COM 口 | MCU、SOC 各最多一个，独占；可发送命令并持续接收输出 |
| Modbus RTU 继电器 | 控制器 COM 口及其 CH1–CH8 | 每个物理通道可关联一个单板及用途名；KL30、KL15 是常用用途，也可没有或有其他用途 |
| USB 摄像头 | 具体物理摄像头输入 | 一个摄像头资源独占归属一个单板；每单板最多六个，分别关联屏幕用途并配置 ROI |

当前继电器仅考虑 PL2303GT 串口连接的 Modbus RTU 八路板；不增加其他板型适配。CH340、PL2303GT 是硬件接入说明，不能作为单板身份。

一块八路继电器板可以将不同通道分给不同单板。KL30、KL15 是被控单板的两条通路，各占对应继电器板的一路，不是两个继电器控制器。

资源可以不齐全。没有安装、没有分配的部件显示“未配置”，不要强制给每个单板生成两路继电器、两个串口或六个摄像头占位资源。缺少资源与已保存绑定配置无效需要区别展示；具体用例能否执行仍由现有预检规则判断。

单板编码、逻辑资源 ID、物理定位是三件不同的事。例如 POWER.kl30 是用例引用的逻辑资源，device 指向单板编码，资源私有 config 保存继电器控制器及通道。改正归属模型时，不自动用旧的自由文本名称覆盖单板编码，也不无声删除或改名已有逻辑资源。

## GUI 工作方式

### 单板总览

按单板设备号查看已登记身份、当前状态，以及是否配置 ADB、KL30、KL15、MCU、SOC、各屏幕摄像头等。资源可缺省，不能为了凑齐界面强制要求硬件齐全。

用户可以先从 ADB 发现列表复制设备号，再将各类物理资源分配给该编码。总览可从 ADB 页面进入或放在宿主 GUI；跨插件归属汇总由宿主 GUI 负责，各插件保持自身切片边界，ADB 插件不直接读取、控制或修改其他插件。

### 物理资源页面

- 继电器：按 COM 控制器和 CH1–CH8 展示直接控制按钮，旁边标明归属单板和用途。动作使用“吸合 / 释放（断开）”，不推断线束的实际通断电效果，不自行增加 KL30/KL15 执行顺序。
- 串口：按 COM 及 MCU/SOC 归属展示输出框、命令输入框和已抽象操作的快捷按钮。
- 摄像头：先打开实际输入预览，确认对应屏幕，再绑定单板和屏幕用途；可交互选择 ROI，并持续显示监控事件。
- ADB：显示具体设备状态，支持命令输入、输出查看、日志读取或校验；fastboot 使用对应命令，不能把 ADB 查询不到直接判定为 fastboot。

摄像头首期监控黑屏、闪黑屏（黑屏后恢复）和冻屏（长时间不变）。花屏待定义，先不实现。具体阈值、时间窗口及串口通信参数在相应插件实现时配置或确认，不从本说明猜测固定值。

### 手动操作、用例和报告

- GUI 为配置、人工控制和实时观察提供入口。
- 手动操作和用例复用相同的长期插件服务；不为每个用例重新打开一套资源。
- 用例运行期间禁止人工控制和修改配置；已启动的采集、预览和状态展示继续工作。
- 继电器压力测试时，GUI 应体现各次吸合/释放及当前状态；不能冻结在运行前的状态。读回状态与命令回执应如实区分，不当作触点物理反馈。
- GUI 载入和展示测试用例，显示运行阶段、当前步骤、带时间戳的执行结果，结束后提供归档报告。
- 启动前只做配置检查。下一用例等待当前用例执行、收尾和报告工作完全退出，不允许重叠运行。

## 代码核对结果与待实现项

截至本次确认：

- 现有核心合约已经提供单板关联、长期服务、插件自有采集线程、ACTIVE 手动锁和运行事件；暂未发现必须修改核心或 DSL 的缺口。
- 现有 ADB 插件有 USB 发现、命令、拉取、日志及基本可用性能力；fastboot 能力和完整模式展示仍需开发。
- 现有继电器插件控制一块八路板，但独立 device_name 分组、固定 KL30/KL15、创建设备时自动生成两路的做法，与本次业务约定不符，仍需在插件内调整。
- CH340 MCU/SOC 插件和摄像头插件尚未实现。
- 宿主 GUI 已有入口、用例/项目载入和结果入口；完整单板资源总览、用例内容展示和时间戳运行事件输出仍需完善。
