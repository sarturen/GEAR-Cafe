# GEAR 合约修订决策

日期：2026-09-18
状态：本轮 11 项关键决策已确认，已落实到 v1 合约与公共接口定义。

## 总原则

优先以明确约束保持简单，不为假想场景增加适配。
只有当前需求下低成本、高收益，或不改就无法实现已接受要求时，才讨论复杂方案。
实现细节采用推荐默认；影响运行判定和使用方式的关键决策交由用户确认。

## 已确认

| 决策 | 结论 |
|---|---|
| D01 扩展边界 | 一个 Resource Type 只有一个所属插件；扩展 ADB 修改 ADB 插件；独立插件可声明新类型；插件互不调用。 |
| D02 公共接口 | 提供独立 gear_contracts 包，固定数据类型、接口、上下文和错误；不包含 Framework、驱动或 Qt 实现。 |
| D03 线程 | Framework 调用插件统一固定工作线程串行执行；Workspace 和其回调在 GUI 主线程；插件内部采集线程自行同步和退出。 |
| D04 生命周期 | 采用长期插件会话和长期设备连接；配置页和用例使用同一插件内部设备服务；每用例只隔离执行状态，结束不重建或关闭长期连接。原“每提交创建 Runtime”提议已撤回。 |
| D05 Preflight | 启动前只检查配置，不检查真实可用性；掉线等问题在实际执行中产生 FAIL。 |
| D06 完全独占 | 取证、清理、报告写入和本次执行任务全部退出后，才允许下一用例；禁止重叠、自动排队和手动命令插入。 |
| D07 会话范围 | 同一 Control Host 只允许一个 GEAR 控制会话，GUI 或 CLI 二选一，空闲时也不启动第二控制会话。 |
| D08 取消和停止 | 统一 stop；执行前取消无测试结果；执行中协作停止为 STOPPED；已有 FAIL 不被覆盖；完整退出后解除独占。 |
| D09 within | 截止时间前必须获得完整满足结果；晚返回 true 仍为超时 FAIL；等待在途调用退出，不强杀，不要求截止时刻额外采样。 |
| D10 插件发现 | 固定 plugins/ 目录，一插件一子目录；放入后重启加载，无额外登记文件；错误和冲突明确报错。 |

## D11 收尾失败：已确认

步骤原本 PASS，但清理或最终报告保存失败，最终结果改为 FAIL。
已有 FAIL 或 STOPPED 保留，原始失败不被收尾错误覆盖。
未开始执行的 REJECTED/DECLINED 仍没有测试结果。
收尾失败后禁止新用例和手动硬件操作，人工处理后重启，不自动恢复。

必须分别记录原始 execution_result 和最终 result/outcome；每条收尾错误记录
发生阶段、UTC 时间、所属插件（如适用）、错误码、消息和原始异常信息。
原始主失败和后续错误分开保留，错误按发生顺序列出。
session_blocked 明确为 true，并说明需要处理原因后重启。
报告写入失败时 report_path 为空，不能把半成品或旧 PASS 当作最终报告。

报告写不进去时，当前状态及 GUI/CLI 仍展示全部诊断，并尝试写入普通会话日志。
日志也写失败时明确说明“诊断未持久化”，不能声称保存成功。
不因此重启一轮设备取证、自动重试或自动恢复。

## 修订交付与检查

1. 将决策同步到架构、Plugin、DSL、Environment 和 Runtime 规范。
2. 提供可直接导入的公共类型和接口定义，保持无运行时依赖。
3. 更新旧结论文本的适用范围，保留历史讨论。
4. 检查 Python 导入及类型引用、文档链接、接口拼写和跨文档规则一致性。
5. 不把定义检查声称为 Framework 或真实硬件测试通过。
